# Go Graph Analysis: Gen8 Neuron Paths

Generated by the research Go analysis pipeline (`cmd/index-builder` → `cmd/graph-builder`).

## What Are Neuron Paths?

**Neuron paths** trace the call chain from Vulkan API entry points down to gen8-specific
code sites in the Turnip driver. Each "neuron" is a terminal code site — a line of C++
that contains A8XX-specific register writes, gen8 chip checks, or A8XX_ constant references.

The graph answers: **If I change this register, which API calls are affected?**

## Analysis Methodology

### 1. Function Discovery (`scripts/index-functions.sh`)
```
ctags --output-format=json --fields=+nKzS src/freedreno/vulkan/*.{cc,h}
```
Discovers all function definitions with file/line/signature metadata.

### 2. Gen8 Site Detection (`scripts/search-gen8.sh`)
```
rg --json '(chip[<>=!]+a8xx|A8XX_|gen8|a8xx)' src/freedreno/vulkan/
```
Finds 3,550+ lines containing gen8-specific code. Classifies each into:
- `gen8-register-write`: Contains A8XX_ register name (e.g., `A8XX_HLSQ_UPDATE_CNTL`)
- `gen8-conditional`: Contains `CHIP >= A8XX` or similar chip check
- `gen8-reference`: Other gen8 mentions (comments, debug strings, feature flags)

### 3. Index Building (`cmd/index-builder`)
Merges ctags + ripgrep results into `IndexGraph`:
- Functions: map of `FuncDef` (name, file, line, signature, gen8_site flag, callees)
- Gen8Nodes: each gen8 code site with enclosing function
- EntryPoints: Vulkan API functions (`vkCmd*`, `tu_Cmd*`)
- Edges: caller→callee relationships extracted from `ctags` references

### 4. Graph Generation (`cmd/graph-builder`)
Three DOT/SVG diagrams (see existing `output/` folder):
- **01_turnip_gen8_architecture**: High-level architecture diagram
- **02_gen8_neuron_paths**: Up to 150 gen8 terminal sites traced back through callers
- **03_call_graph_focused**: Gen8-involved functions and their inter-call edges

## Affected Code Paths (Hack Impact)

The TU8 hacks modify three files. Here's how they connect to the gen8 neuron paths:

```
tu_cs.h (struct tu_cs.dirty + set_register + flush_dirty)
  ├── Used by: ALL register write paths
  │   ├── tu6_emit_vpc()       → A8XX_VPC_* registers
  │   ├── tu6_emit_vs_config() → A8XX_HLSQ_*, SP_* registers
  │   ├── tu6_emit_fs_config() → A8XX_HLSQ_*, SP_* registers
  │   ├── tu6_emit_gras()      → A8XX_GRAS_* registers
  │   ├── tu6_emit_rb()        → A8XX_RB_* registers
  │   └── tu_emit_cache_flush()→ CP_* barrier registers
  │
  ├── tu_cs_flush_dirty()
  │   └── Called before draw state submission
  │       └── tu6_draw_common() → tu_CmdDraw / tu_CmdDrawIndexed
  │
  └── tu_cs_flush_barrier_yolo()
      └── Called at EndRenderPass
          └── tu_CmdEndRenderPass

tu_cs.cc (tu_cs_init dirty initialization)
  └── Called on every command stream creation
      └── tu_cmd_buffer_begin() → vkBeginCommandBuffer

tu_cmd_buffer.cc (YOLO barrier bypass)
  ├── tu_emit_cache_flush()
  │   └── tu6_draw_common() → every draw call
  │
  └── tu_emit_cache_flush_renderpass()
      └── RenderPass barrier insertion points
```

## Running the Analysis

```bash
cd research
devbox shell

# Build index from current Mesa source
./scripts/index-functions.sh  ../mesa/workdir/mesa  output/ctags_index.json
./scripts/search-gen8.sh      ../mesa/workdir/mesa  output/gen8_sites.json

# Merge + generate graphs
go run ./cmd/index-builder  --ctags output/ctags_index.json  \
                            --gen8 output/gen8_sites.json    \
                            --out output/index.json

go run ./cmd/graph-builder   --input output/index.json       \
                             --outdir output/

# Render SVG
sfdp -Tsvg output/02_gen8_neuron_paths.dot -o output/02_gen8_neuron_paths.svg
```
